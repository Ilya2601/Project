# Project
1. Выбор программного средства
Название: GitHub Actions
Обоснование: Выбран как универсальный инструмент для автоматизации рутинных задач разработки: от автоматического тестирования до развёртывания приложений. Он глубоко интегрирован в платформу GitHub, что упрощает настройку и управление процессами непосредственно из интерфейса проекта.
2. Сбор информации
Основные функции
GitHub Actions позволяет создавать автоматизированные рабочие процессы (workflows) для непрерывной интеграции и доставки (Continuous Integration / Continuous Delivery, CI/CD).
Ключевые возможности:

Автоматический запуск тестов при каждом коммите или пуше в ветку.
Сборка и публикация артефактов (бинарных файлов, пакетов).
Развёртывание приложения на облачные платформы (AWS, Azure), статические хостинги или собственные серверы.
Управление зависимостями и выполнение рутинных операций (например, автоформатирование кода).
Интеграция со сторонними сервисами через Marketplace.
Как установить и настроить
Установка не требуется, так как функционал встроен в сам GitHub.
Процесс настройки состоит из следующих шагов:

В корневой директории вашего репозитория создать каталог .github/workflows.
Внутри него разместить файлы конфигурации в формате YAML (*.yml), описывающие ваши workflows.
Определить триггеры запуска (события: push, pull_request, schedule и др.).
Описать «джобы» (jobs) — шаги, которые должны выполняться последовательно или параллельно.
Указать среду выполнения («раннеры») — можно использовать готовые виртуальные машины от GitHub или свои собственные серверы.
Примеры использования
Запуск юнит-тестов Python-проекта после каждого коммита.
Автоматическая публикация сайта на GitHub Pages при слиянии изменений в ветку main.
Проверка безопасности кода перед мержем пулл-реквеста.
Ежедневное резервное копирование базы данных.

4. Оформление документации
Документация оформляется в текстовом редакторе (например, Microsoft Word):

Используются заголовки H1, H2 для разделения разделов.
Ключевые команды и фрагменты кода выделяются моноширинным шрифтом или оформляются в виде блоков кода.
Применяются нумерованные списки для пошаговых инструкций и маркированные — для перечисления функций.
Включаются скриншоты интерфейса GitHub (вкладка "Actions", граф визуализации пайплайна) для наглядности.
